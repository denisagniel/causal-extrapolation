## 15:00 — Item 2: GMM/GLS-efficient combiner over the joint score matrix

**Goal.** User: "Let's finish the R package work" — complete Item 2 (the DiD-score
score-matrix architecture paused earlier the same day). `build_score_matrix()` and
`estimate_score_cov()` existed and were tested but unused: nothing combined the
(possibly correlated) cells they recover into an actual estimate.

**What happened.** Consulted Oracle for the missing architectural/statistical design (new
function, GMM-efficiency claim, integration point) before writing any code, per this
project's escalation policy. Oracle's diagnosis: the real gap was not a DiD-specific score
at all — `build_score_matrix()`/`estimate_score_cov()` are already fully general (they
recover cross-cell correlation from any first-stage backend's per-cell EIFs, regardless of
design). What was missing is the natural generalization of `gls_weights()` (which uses only
per-cell variances, i.e. a diagonal covariance) to the *full* covariance: a GMM/minimum-
distance combiner.

**Implemented exactly per Oracle's design, TDD (tests written first, confirmed failing,
then implemented):**

- **`R/combine_cell_scores.R`** (new) — `combine_cell_scores(score_matrix, values,
  restriction=NULL, target=NULL, cov=NULL, shrink="auto", fallback=c("diagonal","error"),
  omega_scores=NULL)`. Given a restriction `theta = R %*% beta` (R a `J x q` matrix, or a
  length-J grouping vector expanded via the new internal `.build_restriction()`) and a
  target `psi = c'beta`, computes the closed-form optimal-GMM weights `lambda* =
  Sigma_inv %*% R %*% solve(t(R) %*% Sigma_inv %*% R) %*% c`, the combined estimate
  `psi_hat = lambda*'theta_hat`, and its EIF `phi = score_matrix %*% lambda*`. Returns
  `beta`/`vcov_beta`/`phi_beta` (per-free-parameter estimates and their EIFs) alongside the
  combined `value`/`phi`, an honest `se` from the *realized, unshrunk* variance of the
  combined score (never from the shrunk `Sigma` used only to pick the weights), and
  diagnostics (`l1_norm`, `n_negative`) that warn when strongly correlated cells force
  large opposite-signed weights — nominally efficient but finite-sample unstable.
  Falls back to `shrink="diagonal"` (with a warning) when `Sigma` is not reliably
  invertible, or errors if `fallback="error"`.
- **Docstring states the efficiency claim precisely** (per Oracle's exact wording,
  cross-checked): this is the minimum-variance combination *within the class of fixed
  linear combinations of the supplied cell scores*, i.e. optimal-GMM for the linear moment
  system — explicitly **not** the semiparametric efficiency bound for the target itself
  (which would additionally require the restricted-model EIF to lie in the span of the
  unrestricted cell EIFs, among other conditions not established here).
- **`R/path1_aggregate.R`** — added `weighting = "gls-joint"` (third option alongside the
  unchanged `"equal"`/`"gls"`), plus `ids`/`cluster`/`shrink` arguments. Bypasses the
  within-group-then-across-group two-step structure entirely: assembles the full score
  matrix via `build_score_matrix()`, combines directly via `combine_cell_scores()` with
  `restriction = cells$g, target = omega`, and returns the same list shape (`tau_future`,
  `phi_future`, `tau_g`, `phi_g`) so no downstream caller needs to change. Requires a
  reliable row id (`ids`, or `gt_object$ids`); errors clearly rather than falling back when
  neither is available. Did **not** touch the existing `"gls"` path (Oracle: it needs no row
  keys and is strictly subsumed by `"gls-joint"`; upgrading it in place would only add
  surface area).
- **Deferred, per Oracle's recommendation:** the equivalent full-covariance generalization
  for Path 2's `extrapolate_ATT()` WLS step. Structurally different (matrix-valued GLS
  regression weights, not a weighted average) and would require changing the
  `h_fun`/`dh_fun` model contract that user-supplied temporal models are written against —
  separate, interface-breaking work.
- **Investigated and closed, not fixed:** Oracle flagged a suspected latent bug (a group
  with zero observed cells silently producing `tau_mean = 0`). Verified directly: this
  already errors today (`fast_cbind_list()` refuses an empty list before the weight
  computation is even reached) — not a silent-zero bug, just a less-informative error
  message than ideal. Not fixed; not actually broken.

**Verification.** 21 new tests (`test-combine-cell-scores.R`: 21; `test-path1-aggregate.R`:
+4) covering the three closed-form identities Oracle specified as the design's
self-consistency check (unbiasedness `lambda*'R = c'`, the variance identity
`lambda*'Sigma*lambda* = c'A_inv*c`, and the diagonal limit exactly reproducing
`gls_weights()`), the `J=1`/empty-restriction-column/non-invertible-`A` edge cases, the
diagonal fallback and its `fallback="error"` refusal, the `omega_scores` delta-method term
matching `aggregate_groups()`'s, and an end-to-end `path1_aggregate(weighting=
"gls-joint")` test against a synthetic shared-comparator DGP. Full package suite: 0
failures (only pre-existing, unrelated skips/warnings). `devtools::document()` clean on the
second pass (first pass's "could not resolve link" warnings were the expected roxygen
first-pass-ordering artifact, gone on rebuild). `tools::checkDocFiles()` clean.
`devtools::run_examples()` completes without error; `combine_cell_scores()`'s own example
verified directly. NAMESPACE regenerated — this also caught up `build_omega_score`,
`build_score_matrix`, and `estimate_score_cov` (tagged `@export` earlier the same day but
never had `document()` re-run since).
