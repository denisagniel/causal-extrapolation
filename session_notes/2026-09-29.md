## 10:35 — fix ambiguous multi-citation punctuation (natbib `plainnat` auto-bibstyle bug)

**Goal.** User: "The citations aren't compiling correctly." Investigated: compilation itself
was clean (0 overfull hboxes, only the 2 pre-existing undefined-citation warnings), so the
defect was in citation *rendering*, not a compile failure.

**What happened.** Visually inspected the compiled PDF (page 1, page 3) via `pdftoppm` +
image inspection: multi-citations rendered as `[Egami and Hartman, 2023, Heckman and
Vytlacil, 2001]` — square brackets, comma-separated, with no visual distinction between the
comma joining an author to its year and the comma joining two different citations. Root
cause, confirmed by reading `natbib.sty` directly: naming the bibliography style `plainnat`
(`\bibliographystyle{plainnat}`, `main.tex:1769`) triggers natbib's own
`\bibstyle@plainnat` auto-hook (`\bibpunct{[}{]}{,}{a}{,}{,}`), silently overriding natbib's
true defaults (round parens, semicolon-separated) — a documented but easy-to-miss natbib
behavior, disabled only by passing the `nobibstyle` option or, equivalently, an explicit
punctuation option like `round`/`semicolon`.

**Fix.** `\usepackage{natbib}` → `\usepackage[round,semicolon]{natbib}` (`main.tex:16`),
with a comment explaining the mechanism so it isn't silently reintroduced. `round` and
`semicolon` restore natbib's real defaults explicitly and disable the `plainnat` auto-hook
per natbib's own option-handling.

**Verification.** Full recompile (3×xelatex + bibtex): exit 0, 65 pages (unchanged), 0
overfull hboxes, no "Label(s) may have changed," same 2 pre-existing undefined-citation
warnings (unrelated). Re-rendered page 1 and page 3 to PNG and visually confirmed
multi-citations now read `(Author, Year; Author, Year)` — round parens, semicolon-separated,
unambiguous — with no square brackets anywhere sampled.

**Decisions.** None outstanding; this was a mechanical LaTeX-correctness fix (paper-protocol
§3, always hard), not a style choice.
